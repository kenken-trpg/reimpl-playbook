# 04 境界をまたぐ型

実装：`tools/generated/check.py`、テスト：`tests/test_generated.py`

## 同じ形が 2 回書かれる場所を数える

リプレースでは必ず、同じ形が境界の両側で二重に記述される。

- サーバの状態モデル（Python）とブラウザの型（TypeScript）
- 本家データの列挙値と、こちらの `switch`
- データベース行とマイグレーション

二重記述そのものは避けられない（相手の言語が必要としている）。
避けられるのは**食い違うこと**。片側から生成し、CI で stale を落とす。

実際に起きた食い違いは「**サーバにはあるがブラウザの型にない**フィールドが
静かに届かないままになる」形だった。例外も警告も出ない。

## 2 つの規則

1. **内容を比べる。タイムスタンプを見ない。** `--check` はメモリ上に生成して比較する。
   rebase・checkout・キャッシュヒットの後でも正しい。
2. **直し方を出力する。** CI で stale を踏むのは、生成器を書いていない人。

## 生成するものと、しないもの

生成できるのは、片側に**機械可読な定義がある**ものだけ。
Pydantic モデルや dataclass はそう。手で組み立てている巨大な dict はそうではない。

後者を無理に生成しようとすると生成器が第 3 の仕様になる。
**生成しないと決めて手書きにし、その旨を書く**ほうがよい。
