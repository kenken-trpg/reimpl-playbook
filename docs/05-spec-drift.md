# 05 外部仕様の漂流監視

実装：`tools/drift/watch.py`

## テストが原理的に見られない変化

subject が読むもののうち、**自分のリポジトリになく、版管理もされていない**ものがある。
公開されている表計算、ホストされたスキーマ、サードパーティの書き出し形式、
ベンダの API の形。これらは誰かが不具合を見つけるたびに改訂される。
改訂はセルを動かし、シート名を変え、ブロックを広げ、選択肢を増やす。

**フィクスチャで作ったテストはこれを一切見ない。**
フィクスチャは取得した日の写しなので、
実物が離れていってもスイートは緑のまま。最初の報告は
「取り込んだら半分消えた」というユーザからの連絡になる。

## 差分ではなく作業リストを出す

2 つの設計判断で実用になる。

1. **差分を取る前に縮約する。** 生きている文書の生 diff はノイズ。
   コードが依存している事実だけを抜く：節の名前、選択肢の中身、
   ブロックの範囲、ハードコードされた番地の隣にあるラベル。
2. **動くべきコードの名前を一緒に出す。** 監視する事実ごとに、
   それに依存しているシンボル名を持たせる。
   出力が diff ではなく**作業リスト**になる。この文字列が、ただの diff に対する差。

## baseline は承認の記録

`--update` が受理の手続き。baseline の更新を、
それに追随したコード変更と**同じコミット**に入れる。
そのコミットの diff が「上流が何をしたか」「こちらが何を払ったか」の記録になる。
