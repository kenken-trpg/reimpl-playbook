# 事例：chummer-web

この playbook の出どころ。固有の事情を残してあるのは、
抽象化した記述だけだと「自分の案件は違う」で終わるため。

## 何から何へ

- **本家**：Chummer5a — C# / WinForms / .NET 4.8 のデスクトップアプリ。
  テーブルトップ RPG のキャラクター作成ツール。規則はすべて `Chummer/data/*.xml` にある。
- **subject**：Python（FastAPI）+ TypeScript（Next.js）の Web アプリ。
  状態はブラウザ（IndexedDB）が持ち、計算はステートレスなバックエンドが返す。

**フレームワークも基本設計も違うので、コードは 1 行も共有できない。**
共有できたのはデータの解釈と、ファイル形式と、規則の理解だけだった。

## 効いたもの

| 仕組み | 具体的に何が出たか |
|---|---|
| 突き合わせ（34 件の実セーブ） | 残カルマ・残 nuyen の差が品目別の値段ずれまで切り分けられた。「生活様式で +220」のような、手では絶対に見つからない差 |
| 往復一致 | 34 件中 34 件一致を維持。import が読むのに export に書けない項目を都度検出 |
| fidelity | 本家 Chummer.exe が書き出しを読めるかの門。CI ジョブ |
| ピン留め | 上流 master の `<bonus>` スキーマ変更で一晩で壊れる、を構造的に防止 |
| カバレッジ導出 | 未実装 bonus タグを手で数えようとして誤検出した（XML のタグ照合では駄目）。`derived["unimplemented_bonuses"]` が唯一正しい数え方 |
| changelog 断片 | 並行 PR の CHANGELOG 衝突が消えた |

## 予想外だったこと

- **本家のデータのバグがこちらで見つかる。** 全ファイルを 1830 件のテストで解析している
  サードパーティ実装は他になかったので、文字化け・ID 重複・翻訳漏れが落ちてきた。
  上流に PR を 2 本送っている。リプレース側が上流に返せるのは
  **コードではなくデータ**、というのは一般化できる。
- **「わざと違う」の判断が作業の本体になる。** 本家が書いて二度と読まないフィールド、
  保存された価格と現在の価格表の差、career モードでの残高の意味。
  検査を作る時間より、例外に理由を書く時間のほうが長かった。
- **突き合わせ結果の多くは直さない。** 「生活様式の nuyen ずれ」は、
  保存された値だけでは直らず、直そうとすると他のセーブが悪化することが分かったので、
  **理由を書いて放置する**と決めた。それもスクリプトの docstring に残してある。
